## 1. このガイドについて

### 対象読者

| 読者 | 読むべきセクション | やること |
|------|-------------------|---------|
| 事務スタッフ | §1〜5 | draw.io で P&ID の SVG ファイルを作成する |
| エンジニア | §1〜3, §6〜11 | SVG を React に組み込み、ロジックを接続する |

### このガイドで出来ること

別のプラント（工場の配管図）に差し替えるための手順を説明します。プログラミングの知識は不要です。テキストエディタとブラウザが使えればOKです。

### 2つの作成方式

| 方式 | 概要 | 推奨 |
|------|------|------|
| **方式A: draw.io で SVG を作成** | draw.io（無料のブラウザツール）で配管図を描き、SVG ファイルとして書き出す。本ガイドの主題 | 推奨 |
| **方式B: TypeScript 配列で定義** | `sampleData.ts` にノードと配管の座標・接続を直接書く。現行の開発用方式。[§7](#7-現行方式-typescript配列によるプラント定義) で解説 | 開発者向け |

## 2. 全体の仕組み（鳥瞰図）

### 料理に例えると

> **レシピ**（あなたが作るデータ）を**料理人**（アプリ）に渡すと、**料理**（画面の配管図）が出来上がります。
>
> あなたの仕事はレシピを書くことだけ。料理人の仕組みを知る必要はありません。

### 全体ワークフロー

```
Step 1: SVGを作る             ← 事務スタッフ
  draw.io で配管図を描き、各部品にIDを付ける

        ↓

Step 2: SVGの構造を整理       ← 事務スタッフ
  配管・バルブ・タンクをグループに分ける

        ↓  ここから先はエンジニアの仕事  ↓

Step 3: Reactに組み込む       ← エンジニア
  SVGファイルをアプリに取り込む

        ↓

Step 4: ロジック接続           ← エンジニア
  バルブと配管の対応表を作り、CSV訓練シナリオを設定する
```

### システムの3層構造

```
あなたが作るもの:
  [1] 設備と配管の図面 (SVGファイル)     ← 「どんなプラントか」を定義
  [2] 訓練シナリオ     (CSV設定画面)      ← 「どう訓練するか」を定義

触らなくてOK:
  [3] アプリ本体        (React/TypeScript)  ← 自動で動かしてくれる
```

## 3. 画面に何が表示されるか（描画ルール表）

アプリが SVG を表示するとき、各部品は以下のルールで描かれます。**色は仮で描いてOK**です。アプリが状態に応じて自動的に色を切り替えます。

### 要素ごとの一覧

| 要素 | 英語名 | 形 | サイズ | 操作 |
|------|--------|-----|--------|------|
| 供給元 | input | 角丸の四角 | 60 x 50px | 不可 |
| タンク | tank | 角丸の四角 + 下に状態表示 | 55 x 45px | クリックで液あり/なし切替 |
| 出口 | outlet | 角丸の四角 | 50 x 40px | 不可 |
| 接続点 | connection | 小さな丸 | 半径 5px | 不可 |
| 配管（通液中） | pipe | 太い線 | 太さ 6px | 不可 |
| 配管（非通液） | pipe | 細い線 | 太さ 4px（40%透明） | 不可 |
| バルブ（開） | valve | 丸 + 番号 | 半径 14px | クリックで開閉切替 |
| バルブ（閉） | valve | 丸 + 番号 | 半径 14px | クリックで開閉切替 |
| 背景 | — | 方眼紙パターン | 20px 間隔 | — |

### 色のルール

| 状態 | 色 | カラーコード | 意味 |
|------|-----|-------------|------|
| バルブ開 | 緑 | `#22c55e` | 液体が通れる |
| バルブ閉 | 赤 | `#dc2626` | 液体が止まる |
| 配管（通液中） | 水色 | `#22d3ee` | 液体が流れている |
| 配管（非通液） | 灰色 | `#9ca3af` | 液体が流れていない |
| タンク（液あり） | 濃い水色 | `#0891b2` | タンクに液体が入っている |
| タンク（受入中） | 緑 | `#059669` | 液体が流れてきているが空 |
| タンク（空） | 灰色 | `#6b7280` | 液体が来ていない |
| 接続点（到達） | 水色 | `#22d3ee` | 液体が到達している |
| 接続点（未到達） | 灰色 | `#9ca3af` | 液体が到達していない |

**覚え方:**
- **緑** = 開いている・安全
- **赤** = 閉まっている・遮断
- **水色** = 液体が流れている
- **灰色** = 止まっている・空

### タンクの状態表示

タンクの下には状態を示すテキストが表示されます：

| 表示 | 色 | 意味 |
|------|-----|------|
| ●液あり | 水色 | タンクに液体が入っている |
| ○受入中 | 緑 | 液体が流れてきているが、まだ空 |
| 空 | 灰色 | 液体が来ていない |

### まとめ図

```
[input]──配管──(connection)──配管──[tank]──配管──[outlet]
 60x50     線      ●r=5       線   55x45    線    50x40
 水色系   水色/灰              水色/灰 3色変化  水色/灰

          配管にバルブがあれば中間に ○ が出る
                                   r=14
                                  緑=開 / 赤=閉
```

## 4. SVGファイルの作り方

### 4.1 ツールの準備

| ツール | 特徴 | おすすめ度 |
|--------|------|-----------|
| **draw.io (diagrams.net)** | 無料、ブラウザで使える、SVGエクスポート可、P&ID用シェイプあり | ★★★ |
| Inkscape | 無料、高機能、学習コストやや高 | ★★ |
| Visio | 会社にあれば使いやすい | ★★ |
| 手書きSVG | 単純な図なら最速 | ★ |

**おすすめ: draw.io（diagrams.net）**
- ブラウザで即使える: https://app.diagrams.net/
- P&ID 用のシェイプライブラリがある
- SVG エクスポートが簡単

### 4.2 作図の手順

#### Step A: 元画像をインポートする

1. https://app.diagrams.net/ を開く
2. 「デバイス」または「新規作成」を選ぶ
3. 元の P&ID 画像をインポートする（メニュー → ファイル → 画像を挿入）
4. 画像をロックして背景として固定する（右クリック → 「スタイルを編集」→ `locked=1` を追加）

#### Step B: 線や図形でトレースする

元画像の上から、配管・バルブ・タンクなどを線や図形でなぞります。

**重要なルール:**

1. **配管は「バルブで区切った区間ごと」に別々のオブジェクトとして描く**
   - 1本の長い線ではなく、バルブとバルブの間を1本ずつ描く
   - こうすることで、プログラムが区間ごとに色を変えられる

   ```
   ✕ ダメ: 供給元からタンクまで1本の長い線
   ○ 良い: 供給元→接続点（pipe-1）、接続点→タンク（pipe-2）と分ける
   ```

2. **色は仮で良い**
   - プログラムが後から状態に応じて色を上書きします
   - トレース時は見やすい色で描いてください

3. **ラベル（名前）を付ける**
   - タンクには「T-1」「反応器」など分かりやすい名前を付ける
   - バルブには番号（1, 2, 3 ...）を付ける

### 4.3 命名規則（IDの付け方）

draw.io で描いた各オブジェクトに、以下のルールで **ID** を付けます。ID はプログラムがオブジェクトを識別するための名札です。

| 要素 | ID の形式 | 例 |
|------|----------|-----|
| 配管 | `pipe-番号` | `pipe-1`, `pipe-2`, `pipe-3` |
| バルブ | `valve-番号` | `valve-1`, `valve-2`, `valve-3` |
| タンク | `tank-名前` | `tank-T1`, `tank-T2`, `tank-V210` |
| 供給元 | `input` または `input-番号` | `input`, `input-1`, `input-2` |
| 出口 | `outlet` または `outlet-番号` | `outlet`, `outlet-1`, `outlet-2` |
| 接続点 | `connection-番号` | `connection-1`, `connection-2` |

**IDのルール:**
- 半角英数字とハイフン（`-`）のみ使う
- スペースや日本語は使わない
- 全てのIDが重複しないこと（同じIDは2つ使えない）
- 番号は1から順番に付ける

#### draw.io での ID 設定方法

1. オブジェクトを右クリック
2. 「スタイルを編集」を選ぶ
3. `id=pipe-1;` のように ID を追加する

または:

1. オブジェクトを選択
2. 右側のパネルで「配置」タブを開く
3. 「ID」欄に ID を入力する

### 4.4 SVGエクスポート手順

1. メニュー → ファイル → 形式を指定してエクスポート → SVG
2. 設定:
   - 「選択部分のみ」: チェックしない（全体を書き出す）
   - 「背景を含める」: チェックしない（元画像の背景は不要）
   - 「グリッドを含める」: チェックしない
3. 「エクスポート」をクリック
4. ファイル名は `plant-プラント名.svg`（例: `plant-sample.svg`）

### 4.5 よくある間違いと対処法

| よくある間違い | 問題 | 対処法 |
|---------------|------|--------|
| 配管を1本の長い線で描く | プログラムが区間ごとに色を変えられない | バルブで区切った区間ごとに別オブジェクトにする |
| IDを付け忘れる | プログラムがオブジェクトを見つけられない | エクスポート前に全オブジェクトのIDを確認する |
| 同じIDを複数に付ける | どちらか一方しか動かない | IDは全てユニーク（唯一）にする |
| 日本語やスペースのID | プログラムが正しく読めない | 半角英数字とハイフンのみ使う |
| 元画像を消さずにエクスポート | ファイルサイズが大きくなる | 背景画像はロック後、エクスポート時に除外する |

## 5. SVGの構造を整理する

### グループ化のルール

SVG の中身を以下の3グループに整理すると、プログラムから扱いやすくなります。

| グループ名 | 含める要素 | draw.io での方法 |
|-----------|-----------|-----------------|
| `pipes` | 全ての配管（線） | 配管を全て選択 → 右クリック → グループ化 |
| `valves` | 全てのバルブ（丸＋番号） | バルブを全て選択 → 右クリック → グループ化 |
| `equipment` | タンク・供給元・出口・接続点 | 機器を全て選択 → 右クリック → グループ化 |

### レイヤーの使い方

draw.io のレイヤー機能を使うと、グループ管理がさらに楽になります。

1. メニュー → 表示 → レイヤー
2. 3つのレイヤーを作成: 「配管」「バルブ」「機器」
3. 各要素を対応するレイヤーに移動

### 完成時チェックリスト（事務スタッフ向け）

SVG を提出する前に確認してください:

- [ ] 全ての配管にIDが付いている（`pipe-1`, `pipe-2`, ...）
- [ ] 全てのバルブにIDが付いている（`valve-1`, `valve-2`, ...）
- [ ] 全てのタンク・供給元・出口にIDが付いている
- [ ] IDに重複がない
- [ ] 配管がバルブで区切った区間ごとに分かれている
- [ ] ラベル（表示名）が付いている（タンク名、バルブ番号）
- [ ] 元のP&ID画像が含まれていない（背景として使った画像を除外）
- [ ] SVGファイルとして書き出した

## 6. Reactへの組み込みとロジック接続

> このセクションはエンジニア向けです。

### 6.1 SVGインポート方法（概要）

事務スタッフから受け取った SVG ファイルを React コンポーネントとして読み込みます。

```typescript
// SVG を React コンポーネントとしてインポート
import PlantSVG from './assets/plant-sample.svg?react';

// または、SVG の中身を文字列として読み込んで dangerouslySetInnerHTML で描画
import plantSvgRaw from './assets/plant-sample.svg?raw';
```

動的スタイル適用の考え方:
- SVG 内の各要素を `id` で特定し、状態に応じて `fill` や `stroke` を変更する
- 例: `document.getElementById('pipe-1')` で要素を取得し、通液中なら `stroke="#22d3ee"` に変更

### 6.2 ID・labelの利用箇所マップ

SVG ファイルの各プロパティが、アプリの UI でどこに使われるかの対応表です。

| プロパティ | UIでの利用 | 例 |
|-----------|-----------|-----|
| `id` | SVG要素の特定。CSS セレクタ / JavaScript で動的スタイル適用 | `document.getElementById('pipe-1')` で色変更 |
| label（テキスト） | SVG 上のテキスト表示（設備名、タンク名） | 「T-1」「液体A(供給)」と画面に表示 |
| `valveId`（バルブ番号） | バルブ円内の番号表示 + CSV 条件式の `V{n}` と対応 | `valve-3` → 画面に「3」表示、CSV で `V3=OPEN` |
| type（要素種別） | [描画ルール表（§3）](#3-画面に何が表示されるか描画ルール表)の形・サイズ・色・操作可否を決定 | type=tank → 55x45角丸四角、クリックで満/空切替 |
| `x`, `y`（座標） | SVG上の配置座標（方式Bのみ）。方式Aではdraw.io上の配置で決まる | — |
| `from`, `to`（接続先） | 配管の両端を定義。液体到達判定（BFS）の経路計算に使用 | from='input' to='connection-1' → 液が流れる経路 |

### 6.3 バルブ⇔配管の対応表（マッピング）

SVG の要素 ID と、ロジック上のバルブ/配管の対応を定義するマッピングテーブルが必要です。

```typescript
// バルブIDと、そのバルブが制御する配管の対応
const valvePipeMap = {
  'valve-1': { controls: ['pipe-1', 'pipe-2'], from: 'input', to: 'connection-1' },
  'valve-2': { controls: ['pipe-3'], from: 'connection-1', to: 'tank-T1' },
  // ...
};
```

この対応表により:
- バルブをクリックすると、対応する配管の色が変わる
- 液体の到達判定（BFS）で経路を計算できる

### 6.4 条件式・CSVルールとの連携

CSV 条件式の `V1`, `V2` は、マッピングテーブル上のバルブ番号に対応します。
`T1`, `T2` は、タンクの出現順（マッピングテーブルでの定義順）に対応します。

詳細は [§8 CSVルールの設定](#8-csvルールの設定) を参照。

## 7. 現行方式: TypeScript配列によるプラント定義

> この方式は開発・プロトタイピング向けです。本番運用では [方式A（§4 SVG作成）](#4-svgファイルの作り方) を推奨します。

### 7.1 ノード定義 (`nodes`)

`src/data/sampleData.ts` の `nodes` 配列を編集します。

```typescript
import type { PIDNode, Pipe } from '../types';

export const nodes: PIDNode[] = [
  // type: 'source' — 液体供給元（1つ以上必要）
  { id: 'source', x: 50, y: 200, label: '液体A\n(供給)', type: 'source' },

  // type なし — 接続点（パイプの分岐・合流点）
  { id: 'n1', x: 130, y: 200 },

  // type: 'tank' — タンク（液体を貯留、クリックで満/空切替）
  { id: 'tank-T1', x: 370, y: 200, label: 'T-1', type: 'tank' },

  // type: 'outlet' — 出口
  { id: 'outlet', x: 530, y: 240, label: '出口', type: 'outlet' },
];
```

#### ノードのプロパティ

| プロパティ | 型 | 必須 | 説明 |
|-----------|-----|------|------|
| `id` | string | はい | 一意のID。パイプの接続先として使用 |
| `x` | number | はい | SVG上のX座標（ピクセル） |
| `y` | number | はい | SVG上のY座標（ピクセル） |
| `label` | string | いいえ | 表示ラベル。`\n` で改行可能 |
| `type` | string | いいえ | `'source'` / `'tank'` / `'outlet'` / `'inlet'` / `'junction'`。未指定は接続点 |

#### ノードタイプの動作

| タイプ | SVG表示 | クリック | BFS動作 |
|--------|---------|---------|---------|
| `source` | 矩形（60x50） | 不可 | 液あり→BFS起点 |
| `tank` | 矩形（55x45）+状態表示 | 満/空切替 | 液あり→BFS起点、空→通過遮断 |
| `outlet` | 矩形（50x40） | 不可 | 通常ノード |
| 未指定 | 小円（r=5） | 不可 | 通常ノード |

### 7.2 パイプ定義 (`pipes`)

```typescript
export const pipes: Pipe[] = [
  // バルブなし（常時開通）
  { id: 'p1', from: 'source', to: 'n1', valveId: null },

  // バルブあり（V1で開閉制御）
  { id: 'p2', from: 'n1', to: 'n2', valveId: 1 },
];
```

| プロパティ | 型 | 必須 | 説明 |
|-----------|-----|------|------|
| `id` | string | はい | 一意のID |
| `from` | string | はい | 始点ノードID（nodes に存在する必要あり） |
| `to` | string | はい | 終点ノードID（nodes に存在する必要あり） |
| `valveId` | number \| null | はい | バルブ番号（null = バルブなし・常時開通） |

**注意**: パイプは双方向に流れます。`from`/`to` の向きは描画方向のみに影響します。

### 7.3 自動導出される値

以下は `nodes`/`pipes` から自動的に導出されるため、**手動で定義する必要はありません**：

- `allValveIds` — 全バルブID一覧
- `allTankIds` — 全タンクID一覧
- `nodeMap` — ノードID→ノードのルックアップ
- `tankIdMap` — CSV短縮名（T1, T2）→ノードIDのマッピング
- `initialValves` — 全バルブ閉の初期状態
- `initialTankFilled` — source=液あり、tank=空の初期状態

### 7.4 座標の決め方

キャンバスサイズはノード座標から自動算出されます：
- 幅 = 最大X座標 + 70px
- 高さ = 最大Y座標 + 60px

座標設計のコツ:
1. **source** を左端（x=50程度）に配置
2. **outlet** を右端に配置
3. 接続点は等間隔（80px程度）で配置
4. タンクは分岐後に配置
5. ノード同士が重ならないように最低60px間隔を確保
6. バルブはパイプの中点に自動配置されるため、パイプが短すぎないよう注意

```
例: x=50, 130, 210, 290, 370, 450, 530 → 80px間隔
    y=200（メインライン）, 280（分岐ライン）
```

## 8. CSVルールの設定

### 8.1 フェーズ定義 (phases)

```csv
phase_id,phase_name,order
preparation,準備,1
operation,運転,2
shutdown,停止,3
```

### 8.2 ステップ定義 (steps)

```csv
phase_id,step_id,step_name,description,instruction,condition,order
preparation,prep-1,初期確認,全バルブ閉確認,全バルブが閉じていることを確認,ALL_VALVES_CLOSED,1
preparation,prep-2,供給開始,V1を開ける,バルブ1を開けてください,V1=OPEN,2
```

### 8.3 安全ルール定義 (rules)

```csv
rule_id,rule_name,condition,error_message,severity,phases
rule-001,供給未開放,OPENING:V2+ AND V1=CLOSED,V1を先に開けてください,warning,all
rule-002,空タンク送液,OPENING:V6 AND T1=EMPTY,T1が空です,critical,all
```

### 8.4 条件式の文法

| 条件式 | 意味 |
|--------|------|
| `V{n}=OPEN` | バルブn が開いている |
| `V{n}=CLOSED` | バルブn が閉じている |
| `T{n}=FILLED` | タンクn に液がある |
| `T{n}=EMPTY` | タンクn が空 |
| `ALL_VALVES_CLOSED` | 全バルブ閉 |
| `ALL_VALVES_OPEN` | 全バルブ開 |
| `OPENING:V{n}` | バルブn を開けようとしている（ルール用） |
| `OPENING:V{n}+` | バルブn以上を開けようとしている |
| `CLOSING:V{n}` | バルブn を閉じようとしている |
| `A AND B` | AかつB（AND は OR より優先度高） |
| `A OR B` | AまたはB |

**タンク番号の対応**: `T1`, `T2`, ... は `nodes` 配列のタンク出現順に対応します。

## 9. トポロジーバリデーション

dev モード（`npm run dev`）で起動すると、自動的にトポロジーの整合性チェックが実行されます。

検証項目：
- ノードIDの重複がないか
- パイプIDの重複がないか
- パイプの from/to が存在するノードを参照しているか
- バルブIDの重複がないか

エラーがあればブラウザのコンソールに警告が表示されます。

テストで手動検証する場合：

```typescript
import { validateTopology } from './data/topologyValidator';
import { nodes, pipes } from './data/sampleData';

const result = validateTopology(nodes, pipes);
console.log(result.valid, result.errors);
```

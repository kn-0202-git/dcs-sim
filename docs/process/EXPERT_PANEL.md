# 専門家パネル運用

## 1. 目的
- 論点ごとに必要な専門家だけを招集し、レビューの質と速度を両立する。
- 複数LLM/複数プロジェクトでも同じ意思決定プロセスを再現する。

## 2. 役割

### ファシリテーター（常時参加）
- 依頼内容を論点に分解する。
- 招集トリガーに従って専門家を選ぶ。
- 意見の衝突を整理し、採用案/却下案/保留を明示する。
- issueログの `expert review:` に最終決定を記録する。

### 専門家ロスター（必要時のみ招集）
| 専門家 | 主な責務 | 招集トリガー |
|---|---|---|
| AIエンジニア | LLM運用、プロンプト設計、自動化 | LLM運用改善、スキル化、自動生成品質 |
| 化学プラント | P&ID妥当性、手順安全性 | 配管モデル、バルブ手順、物理挙動 |
| 教育者 | 教材としての理解容易性 | 訓練モード、手順文言、段階設計 |
| UIUX | 操作性、視認性、誤操作防止 | 画面遷移、ラベル、色、可読性 |
| シニアエンジニア | 設計品質、保守性、テスト戦略 | アーキテクチャ変更、リファクタ、品質課題 |
| PM | スコープ、優先度、納期 | 仕様追加、実施順序、MVP判断 |
| セキュリティ | 入力検証、脅威分析 | ファイル取込、外部入力、権限、XSS |

## 3. 招集ルール
1. まずファシリテーターが「論点・リスク・期限」を3行で整理する。
2. 招集トリガーに一致した専門家だけを呼ぶ（全員同時招集はしない）。
3. 各専門家は「懸念点 / 推奨案 / 代替案」を1セットで返す。
4. ファシリテーターが最終案を確定し、issueログに記録する。

## 4. issueログへの記録フォーマット
`docs/logs/issues/ISSUE_LOG_TEMPLATE.md` の `expert review:` を使用し、次を記録する。
- topic: 論点
- experts: 招集した専門家
- conclusion: 採用した方針
- unresolved: 未解決事項（なければ「なし」）

## 5. 運用モード
- 半日最小版: ファシリテーター運用 + 招集トリガー適用 + issueログ記録。
- 2-3日しっかり版: `process-check`/CIで、必要な `expert review` 記録を自動検証。
